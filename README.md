# 私信邮件配置

网站留言发送到邮箱，不再公开展示。邮件账号与授权码只配置在后端环境变量中，不能上传 GitHub，也不能写进前端。

## 163 邮箱

1. 登录网页版 163 邮箱，在设置中找到 POP3/SMTP/IMAP 服务（界面名称可能不同）。
2. 开启 SMTP 服务，按账号要求完成验证，生成客户端授权码。一般无需购买额外邮件服务，具体以邮箱账号规则为准。
3. 在 SnapDeploy 的后端应用环境变量中设置以下项目，然后重启或重新部署后端：

| 环境变量 | 值 |
| --- | --- |
| SMTP_HOST | smtp.163.com |
| SMTP_USE_SSL | 1（使用 163 的 SSL 端口 465） |
| SMTP_USER | 18991739840@163.com |
| SMTP_PASSWORD | 邮箱生成的客户端授权码，不是登录密码 |
| SMTP_FROM | 18991739840@163.com |
| CONTACT_EMAIL | 18991739840@163.com |

本项目不自动读取 .env。部署时必须使用平台环境变量；不要将实际授权码提交到仓库。

## 部署与验证

- 启动命令：`uvicorn main:app --host 0.0.0.0 --port $PORT`，平台应用端口必须选择 `8000`。不要添加名为 `SMTP_PORT` 的变量；邮件端口由 `SMTP_USE_SSL=1` 在代码中使用 465，避免平台误把邮件端口当成应用端口。需要持久化保存 portfolio.db，以保留访客数与防重复记录。
- 更新后端 main.py，并在平台确认实际运行的是新版本；只推送前端不会更新 SnapDeploy。
- 未配置 SMTP：提交返回 503，不会显示邮件成功。
- 配置完成后，从网页提交一条独特测试留言，查看 163 收件箱及垃圾邮件文件夹。
- 成功的 API 响应为 `{"ok":true,"email_sent":true}`，表示 SMTP 服务接受了邮件，最终是否进收件箱还取决于邮箱服务。
- 同一个 request_id 不会再次发送；相同姓名与内容在五分钟内也会被拦截。前端不要自动重试 POST。
- SMTP 中断时可能无法确认是否已接收，返回 502 并保留防重复记录。请先检查邮箱，不要反复点击提交。
- `/api/messages` 永远返回空数组。历史留言数据库没有被删除，但不再通过此接口公开；不要把数据库上传仓库。
- SQLite 防重记录不保存新留言正文。SMTP 发信配额由邮箱服务决定；本应用尚无反机器人挑战，大规模公开使用前需额外加入限流。

## 本地验证

安装依赖后运行 `python -m unittest discover -s tests -v`。测试使用临时数据库与模拟发信，不会发送真实邮件或改动生产数据库。
